How to: research with language models

Cultural Data Analysis · the toolkit llm_tools.py for your own projects

The Week 4 notebooks use a small toolkit, llm_tools.py. You can use it in your own projects to ask models, save their answers, let a model code texts and check the coding. The project template goes through a whole project step by step. This page is for looking things up.

1. Set up

In a Colab code cell:

import urllib.request
urllib.request.urlretrieve('https://raw.githubusercontent.com/goto4711/cdai/main/llm_tools.py', 'llm_tools.py')
from llm_tools import *

Keys go into Colab's secrets (the key symbol on the left, then switch on Notebook access), never into your code. The model name decides which key you need:

  • gemini-3.5-flash-lite: a name that starts with gemini needs GEMINI_API_KEY, free at aistudio.google.com.
  • openai/gpt-4.1-mini: a name with a / goes through OpenRouter and needs OPENROUTER_API_KEY. OpenRouter has most models, but costs money: you need some credit on your account.
has_key('openai/gpt-4.1-mini')        # True if the key for this model is there
openrouter_models('mistral')          # the models on OpenRouter, with prices; no key needed

2. Ask

answer = ask('Name three Dutch painters.', model='gemini-3.5-flash-lite')
print(answer)

temperature sets the randomness (1.0 is the usual default) and system adds an instruction for the whole conversation. Without a key, ask() stops with a message that says which key is missing.

3. Collect many answers

One answer is one sample. Ask every prompt several times, and change one thing at a time: the model, the language, the wording.

answers = collect({'en': 'Name 20 important dates in world history.',
                   'nl': 'Noem 20 belangrijke data uit de wereldgeschiedenis.'},
                  models=['gemini-3.5-flash-lite', 'openai/gpt-4.1-mini'],
                  runs=10, file='answers.csv')

Every answer goes into the CSV file straight away, with the date, the model, the settings and the tokens. If the cell stops, run it again: it goes on where it stopped. Download the file at the end, because files in Colab disappear when the session ends.

4. Read the answers

Ask for a format you can read with code, e.g. one item per line or JSON.

parse_dates('1492 | Columbus reaches the Americas\n221 BCE | Qin Shi Huang unifies China')
# [(1492, 'Columbus reaches the Americas'), (-221, 'Qin Shi Huang unifies China')]

parse_json('Here you go: [{"id": 0, "region": "Europe"}]')
# [{'id': 0, 'region': 'Europe'}]

5. Let a model code texts, and check it

Write your categories and instructions as you would for a human coder:

categories = {'region': ['Europe', 'Africa', 'Asia', 'Americas', 'Global']}
instructions = 'These are events from world history. Where did each event mainly take place?'
print(coding_prompt(instructions, categories))      # what the model receives: report it
codes = code_with_llm(texts, instructions, categories, file='codes.csv')

code_with_llm() works with any model name, e.g. model='anthropic/claude-haiku-4.5'. Codes the model could not give become unclear: look at them.

Then check the coding. Draw a sample and code it yourselves before you look at the model's codes:

sample = validation_sample(codes, n=20)
mine = ['Europe', 'Asia', ...]                     # your codes, in the order printed
agreement(mine, sample['region'])
# items 20, percent ..., kappa ...

Kappa is the agreement beyond chance: 1 is perfect, 0 no better than chance. As a rule of thumb, above 0.8 is very good, 0.6 to 0.8 good, below 0.4 weak. If it is low, change the categories or the instructions and try again.

6. Compare

shares(df, 'model', 'region')                  # the share of each region per model
jaccard({1492, 1789, 1914}, {1492, 1914, 1945})  # overlap of two lists: 0.5
within_between(sets, labels)                   # same model vs different models
brier(forecasts['probability'], forecasts['outcome'])   # score forecasts: 0 is perfect

7. Without a key

You can try everything on data we collected beforehand: llm_dates_2026.json (dates of world history from five models) and llm_forecasts_2026.json (forecasts from six models), in the course data. The project template uses them when there is no key.

8. Report what you did

Others must be able to repeat your study. Report the exact model names and when you asked them; the prompts and settings (temperature, number of runs); how you read and coded the answers, with the coding prompt; the answers that failed; and the agreement of your check. The CSV files from collect() and code_with_llm() hold most of this.

9. When it goes wrong

  • No key: add the key named in the message to Colab's secrets and switch on Notebook access.
  • Too many requests: free keys have limits per minute and per day. ask() waits and tries again; otherwise wait and run the cell again.
  • Answers in the wrong format: say in the prompt exactly what you want, give an example, and read some answers yourself.
  • Costs: check the prices with openrouter_models() and try a few requests before you send hundreds.

All functions and their options are listed at the top of llm_tools.py. Every function also has a help text: help(collect).
