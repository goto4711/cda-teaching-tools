Build an app with UvA AI Chat

Cultural Data Analysis · Week 1: Python · a group exercise, about 30 minutes

In the lecture you saw that an image is an array of numbers. Today your group builds a small app that shows exactly that: you draw a picture on a grid, and the app shows the picture as a list of lists of 0s and 1s. You don't write the code yourselves. You write the specification, UvA AI Chat writes the code, and you test whether the app does what you asked.

A 3 on the grid. Its top row as numbers: [0, 1, 1, 1, 1, 0, 0, 0]

You need: one laptop per group, logged in to UvA AI Chat with your UvAnetID. It is free.

1. Write the specification · 5 minutes

A specification says what the app must do, as precisely as you can. Start from ours below, then change it as a group: add one thing you would like the app to do, and say how it should look.

Make me a small web app as one HTML page, so that I can try it here in the chat.

- An 8 by 8 grid of squares, all white at the start.
- Clicking a square switches it between white and black.
- Below the grid, show the grid as a Python list of lists: 0 for white, 1 for black, one row per line. It changes with every click.
- A button "Count black pixels" that shows how many squares are black.
- A button "Clear" that makes all squares white again.

Keep the code short and put a comment above each part, so that a beginner can read it.

2. Build it · 10 minutes

  1. Paste your specification into UvA AI Chat. The app appears as an artifact next to the chat: try it there.
  2. Something is wrong or missing? Don't edit the code. Describe the problem to the chatbot, as precisely as in your specification: "When I click a square twice, it stays black. It should turn white again."
  3. Note down every change you had to ask for. You will need the list in step 4.

3. Test it, and read the code · 5 minutes

Test, don't trust. Check each point by hand, and tick it only when it works:

  1. Click the square in the top-left corner. Does the first number of the first row become 1?
  2. Click the same square again. Is it back to 0?
  3. Draw a digit, for example a 3, like the one on the NumPy slide of the lecture. Count the black squares yourself: does the button give the same number?
  4. Are there 8 rows of 8 numbers, in the right order (the top row of the grid first)?
  5. Click Clear. Are all numbers 0, and is the count 0?

Then open the code behind the artifact. It is JavaScript, not Python, but you know the ideas from the lecture (remember the loops in four languages). Find the four programming patterns:

Data structureWhere is the grid kept? Look for a list of lists (in JavaScript: an array of arrays, written with [ ]).
Sequential: a loopWhere are the 64 squares made? Look for for.
Event drivenWhat happens when you click? Look for click or addEventListener.
A decisionHow does a square know whether to turn black or white? Look for if, or for ? :, a short way to write if-else.

4. Together · 10 minutes

  1. Two or three groups show their app on the projector, and say which changes they had to ask for. Same specification, different apps: what differs?
  2. The class agrees on one new feature, and every group asks for it in the same words. For example:
    • a 16 by 16 grid;
    • a button that mirrors the picture from left to right;
    • shades of grey from 0 to 16 instead of black and white, as in the digits of the lecture.
  3. Test the new feature with the checklist. Did every group get the same thing? What does that tell you about code written by a chatbot?
Why we do this. An app is made of the same few building blocks you met this week: a list of lists, a loop, an event and an if. A chatbot can write them for you, but only you can say what you want, and only you can check that the result is right. That is the point of this course too: the computer does the counting, you do the asking and the checking.
